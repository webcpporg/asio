[#asio-cobalt]
== Use Cobalt with Asio

Cobalt now owns its coroutine facade, compiled core, runner and optional SSL
wrapper in a separate library. Include `webcpp/cobalt/` headers and use
`webcpp::cobalt` with `webcpp::asio`. Native core and plain I/O names are Boost
identities; Wasm selects compatible shipped implementations. Consumers do not
patch Boost or depend on replacement-header search order.

[#asio-cobalt-example]
=== Tutorial: wait for a timer in co_main

The compiled example moved to `libs/cobalt/example/asio_cobalt.cpp`. The
link:{webcpp-libs}/cobalt/{webcpp-page}#cobalt-tutorial[Cobalt timer tutorial]
shows the complete source, prerequisites, command and checked output. The
application still writes `co_main`; the runner owns `main`.

[#asio-cobalt-build]
=== How to link the integration

Select `/webcpp/cobalt//cobalt` for an application defining `co_main`, or
`/webcpp/cobalt//core` when the application supplies `main` and drives its own
context. Asio declares no Cobalt target of its own. Do not also link a system
Cobalt archive or another runner.

The link:{webcpp-libs}/cobalt/{webcpp-page}#cobalt-building-external[external build recipe]
lists the shipped sources and dependencies for another build system. Apply
executor, PMR, exception and thread configuration consistently to every source.
The link:{webcpp-libs}/cobalt/{webcpp-page}#cobalt-exceptions[exception-mode contract]
retains the informational warning for
https://github.com/boostorg/cobalt/issues/287[Cobalt issue 287]. Result-based
error handling does not repair that pending-coroutine move path.

[#asio-cobalt-ssl]
=== Use the corrected SSL stream

Include `webcpp/cobalt/io/ssl.hpp`. Select `/webcpp/cobalt//cobalt_ssl` with the
runner or `/webcpp/cobalt//io_ssl` with a custom main. These optional targets
share Asio's source-built OpenSSL and CA provider; plain Cobalt does not link TLS.
Browser HTTPS/WSS instead uses host TLS and its certificate policy.

Prepare the context with `webcpp::asio::make_tls_client_context`, check its
result and configure hostname verification and SNI as described in
<<asio-ca-certificates>>. Cobalt's SSL context is the selected Asio context type.
The corrected native SSL stream is an explicit exception to native Boost type
identity; it is not a modification to an installed Boost header.

[#asio-cobalt-ssl-state]
==== Handshake and stream state

The link:{webcpp-libs}/cobalt/{webcpp-page}#cobalt-ssl-state[Cobalt SSL state contract]
describes STARTTLS, buffered handshakes, cancellation and shutdown. After a failed
or cancelled handshake the corrected wrapper blocks application I/O instead of
falling back to plaintext. Keep the concrete SSL stream type for the corrected
native composed read/write overloads; type erasure can select upstream behavior.

[#asio-cobalt-ssl-tests]
==== Run the local wrapper checks

From the configured superproject root:

[source,bash]
----
b2 -a variant=release libs/cobalt/test/tls//tls
b2 -a toolset=clang-wasip3 variant=release libs/cobalt/test/tls//tls
----

The link:{webcpp-libs}/cobalt/{webcpp-page}#cobalt-testing[TLS and cancellation tests]
use real local peers and temporary certificates with TLS 1.2 and 1.3. WASI tests
need network grants but no filesystem CA preopen. Keep native upstream
cancellation limitations distinct from the corrected SSL path.

[#asio-cobalt-runner]
=== Why the Wasm runner changes

Native core and runner sources remain byte-identical to Boost. The browser
runner drives WebCPP's bounded context, offering a scheduling opportunity after
a full turn of at most the configured handler count, currently 100 by default.
It cannot interrupt a long handler. Configure that value as in
<<asio-run-default>>, consistently for the runner and application.

The WASI runner omits unsupported POSIX signal registration. Internal Asio and
Cobalt cancellation remain available, but automatic SIGINT/SIGTERM shutdown does
not. A host must use an explicit application shutdown protocol; stopping a
context or terminating a component does not guarantee pending-operation cleanup.

[#asio-cobalt-status]
=== Completion and limitations

The browser runner preserves the coroutine's exit status, including after an
Asyncify suspension. WASI SDK 34 command startup maps nonzero results to host
status 1; tests distinguish that failure result from a trap. See
link:{webcpp-libs}/cobalt/{webcpp-page}#cobalt-testing[Cobalt's test contract]
for the current validation gates and native upstream limitations.

[#asio-cobalt-verify]
=== Checks and historical suspension storage

The runner tests now belong to Cobalt:

[source,bash]
----
b2 libs/cobalt/test//cobalt
b2 toolset=emscripten libs/cobalt/test//cobalt
b2 toolset=emscripten libs/cobalt/test//cobalt_asyncify
----

The historical 2026-10-14 Asyncify probe measured a maximum of 1,088 bytes in
Release with the default link, 384 with an optimized link, and 1,032 in Debug.
These describe the earlier source revision. They are suspension storage, not
binary size or a bound on arbitrary application call depth. Current migration
measurements must be recorded separately; the configured stack remains 8,192 bytes.

[#asio-cobalt-sizes]
=== Historical reference: release binary sizes

The timer example from the earlier integrated distribution was measured with Emscripten 6.0.11, Boost 1.92,
{cpp}20 and Node 26.7.0 on macOS arm64, on 2026-10-15. Each of the twelve
configurations used its own build directory, with `variant=release`,
`NDEBUG`, matching compile and link optimization flags, and an 8192-byte
Asyncify suspension stack. Compile commands were checked for the requested
optimization and exception mode; LTO objects were checked for LLVM bitcode.

All 24 page modules completed once under Node, reporting status zero and
exactly `cobalt slept`. The `-O2` modules also passed in local HeadlessChrome
153.0.8010.12 under both suspension variants and both exception modes.
The other optimization profiles were not individually tested in Chrome.
These are complete modules, including the Cobalt runner and the selected
library code, without the Node test harness. Sizes are uncompressed bytes;
JavaScript excludes the shared loader and HTML. Add the matching Wasm and
JavaScript columns for the two-file payload. These measurements do not
isolate the size added by Cobalt and are not runtime-memory measurements.
