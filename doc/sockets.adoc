[#asio-sockets]
== Sockets and transports

=== Explanation: native sockets and browser capabilities

Native builds use Boost.Asio's socket types directly. Emscripten builds use
webcpp protocol and socket templates with the supported Boost signatures.
They do not call SOCKFS or invent IP addresses through getaddrinfo. Browser
TCP and UDP are unavailable unless a transport supplies the operations.

Opening and closing an object succeeds without acquiring a network resource.
Opening an already open object reports `already_open`. With the default
transport, network operations return `operation_not_supported`: synchronous
calls return immediately, and asynchronous calls post their completion.
The `error_code&` overloads do not throw; throwing overloads are present only
with exceptions enabled. Queries such as `is_open` describe the local object.

=== How-to: provide a transport

Specialize `browser::transport<Protocol>` for a protocol to provide its network
operations. The specialization must be visible before first use in every
translation unit using that protocol. A relay is a separate transport, not a
change to an individual socket's error policy. Boost.Beast's `tcp_stream`
contains a Boost socket; a relay reaches Beast as an explicitly named next layer.

=== Reference: supported operations

Stream sockets support connect, read/write_some, send/receive, shutdown,
options, endpoint queries and non-blocking settings. Datagram sockets add
bind, send_to and receive_from. Acceptors support bind, listen and accept,
including asynchronous acceptance into an existing or returned socket.
Callbacks and deferred tokens use the same asynchronous initiation.
See <<asio-invariant-12>> and the generated API reference for overloads.

=== Explanation: the resolver preserves names

On Emscripten, forward resolution constructs one entry with the original host
and service, an unspecified IPv4 address and the service port. This is not a
DNS lookup. A browser stream can retain the name without rewriting a client's
resolve step. A plain socket still refuses connecting to this entry.

An empty service means port 0. Decimal services accept 0 through 65535;
`http` and `ws` select 80, and `https` and `wss` select 443. Named services
are refused with `numeric_service`. Other services report `service_not_found`.
Reverse resolution reports `operation_not_supported`. Async completion is
posted; cancel does not retract a result already computed at initiation.
See <<asio-invariant-13>>.
